# Архитектура C4

Лаборант добавляет прибор, выдаёт его студенту, фиксирует возврат и сохраняет сводку по выдачам. Студент получает прибор у лаборанта и не обращается к API напрямую. Внешние информационные системы в этом сценарии не используются.

- [Редактируемые схемы diagrams.net](architecture.drawio)
- [Экспорт трёх схем в PDF](architecture.pdf)

## Context

Лаборант пользуется системой через HTTP-клиент. Система хранит каталог, историю выдач и выгруженные сводки.

## Container

| Компонент | Ответственность |
|---|---|
| API Gateway (Nginx) | Публикует один порт и направляет запросы в каталог, выдачи и отчёты по префиксам путей. |
| Catalog API | Ведёт каталог приборов. Поддерживает CRUD и проверяет уникальность инвентарных номеров. |
| Loans API | Регистрирует выдачу и возврат. Перед выдачей запрашивает прибор у Catalog API. |
| Reports API | Запрашивает журнал у Loans API, подсчитывает активные и закрытые выдачи, сохраняет JSON-сводку. |
| PostgreSQL 16 | Одна база `app` с таблицами `equipment` и `loans`, том `db_data`. Внешний порт не публикуется. |
| Файловое хранилище | Том `report_data` хранит неизменяемые выгрузки JSON. Сводку можно открыть после перезапуска. |

Файловое хранилище выбрано вместо Redis, потому что сводка — самостоятельный снимок данных на момент запроса. Её нужно сохранять по идентификатору и выдавать после перезапуска. Кэш каталога для этого сценария не нужен.

## Component

Внутри Loans API обработчики маршрутов валидируют входные данные, выполняют HTTP-запрос к каталогу и вызывают `LoanStore`. Именованный `HttpClient` отвечает за адрес каталога и тайм-аут. `LoanStore` записывает изменения параметризованными запросами. Частичный уникальный индекс PostgreSQL исключает две одновременные активные выдачи одного прибора. Повторное подтверждение возврата сохраняет исходное время возврата.
